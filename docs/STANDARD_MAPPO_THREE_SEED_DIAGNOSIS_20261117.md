# Standard MAPPO 三种子训练结果诊断（2026-11-17）

> **后续决策更新（2026-11-17）：** 用户已决定不再沿用本报告建议的
> clean 8-slot/u400 父策略，而是按历史 6-slot、progress-aware 安全执行

## 1. 审查定位与边界

本报告审查当前 `3U+8S+2D` Standard MAPPO 三训练种子（23、41、67）的已有配置、训练日志、周期评估、checkpoint 清单和历史结果合同。

本次只做静态证据审计：未启动训练、未重新评估、未访问外部资料。

当前目录不存在 ARA Seal Level 2 所要求的 `PAPER.md`、`logic/*`、`trace/*` 和 `evidence/*`，也没有 Level 1 通过记录。因此，本报告仅借用 `ara-rigor-reviewer` 的六维语义审查框架，**不是正式 ARA Seal Level 2 报告**，也不生成 `level2_report.json`。

## 2. 结论先行

当前“效果比以前差”不是单一训练故障，而是三个因素叠加：

1. **确定原因：最终查看的是 u600，但冻结论文协议要求共同使用 u400。** 从 u400 继续训练到 u600 后，seed 23 和 41 明显退化；三种子平均 CFMS 从 0.408 降到 0.275，碰撞率和超时率各增加 6.67 个百分点。
2. **确定原因：历史结果与当前结果不是同一实验合同。** 历史系统使用 6 个障碍槽、FACS/STAR selector 和 `causal_ttc_progress_projection_v2`；当前 clean Standard 使用 8 个障碍槽、禁用 selector 和 `causal_ttc_projection_v1`。任务、环境和学习器指纹全部不同，不能表述为“同一个 Standard MAPPO 从 0.68 降到 0.40”。
3. **强证据支持的机制：当前策略与安全执行层严重不对齐，并形成执行固定点。** u400 的 material intervention 为 0.699–0.804，初始联合保护介入为 0.569–0.654，安全层吸收固定点 episode 比例为 0.25–0.35。当前失败主要表现为超时，而不是单纯碰撞。

没有发现 NaN、异常终止或训练进程报错的证据。现有结果更像是**稳定但非单调的策略学习、合同变化和安全执行层吸收动作**，而不是数值发散。

因此：

- 不应继续以 u600 作为论文 Standard 父策略；三种子统一回到预注册的 `update_0400.pt`。
- 不能用历史 0.68 结果证明当前 clean Standard 已复现原能力；历史结果只能作为合同不兼容的能力背景。
- 目前不应直接开始正式 CSA、Lagrangian 或正式测试。应先确认 u400 父策略是否满足一项**预先冻结的父策略能力门槛**。
- 不需要立即重训 Standard。现有三条运行都保存了 u400 checkpoint，可先利用已保存工件完成诊断性父策略确认。

### 3.2 实际训练末端 u600

- CFMS：0.408 → 0.275，**下降 13.33 个百分点**；

## 4. 与历史结果的可比性审计

### 4.1 合同不一致

| 项目 | 历史 8S+2D 结果 | 当前 clean Standard |
|---|---|---|
| 观测维度 | 52 | 66 |
| 全局状态维度 | 156 | 198 |
| obstacle slots | 6 | 8 |
| selector | `facs_star_v0` | `disabled_archived_v1` |
| TTC | `causal_ttc_progress_projection_v2` | `causal_ttc_projection_v1` |
| task fingerprint | `bd138...` | `a25378...` |
| environment fingerprint | `40cd0...` | `f2d967...` |
| learner fingerprint | `b7dd2...` | `0ee65...` |

历史归档自身也明确写明不得从这些 checkpoint 恢复、调参或初始化当前研究。论文协议同样明确指出：历史六槽/旧 selector checkpoint 不得进入正式表格，也不得作为 CSA 父策略。

因此，历史 CFMS=0.68 与当前 u400 均值 0.408 之间的差距，混合了：

- 不同观测容量；
- selector 的存在与否；
- TTC/恢复语义变化；
- 不同 learner 和环境合同；
- 训练 update 与评估样本量差异。

它不是纯粹的“训练质量下降”。

### 4.2 同一 40 layouts 的诊断性比较

历史 200-layout 结果包含 117000–117199；当前周期评估使用其中的 117000–117039。仅比较这 40 个相同 layouts：

| 系统 | 成功 | 碰撞 | 超时 |
|---|---:|---:|---:|
| 历史集成系统 | 26/40 = 0.650 | 6/40 = 0.150 | 8/40 = 0.200 |
| 当前 seed-23 u400 | 16/40 = 0.400 | 4/40 = 0.100 | 20/40 = 0.500 |

相同 layouts 下，当前系统碰撞并未增加，主要是**多出 12 个超时**。这说明结果差距不能归因于“当前抽到的 layouts 更难”；更符合“动作被安全执行层长期吸收或制动，导致任务无法在时限内完成”的解释。

注意：这仍不是严格的因果消融，因为策略、观测、selector 和安全合同同时变化。它只能定位失败形态，不能单独证明是哪一个安全模块造成的。

## 5. 原因分级

### 5.1 已由现有工件确认

#### 原因 A：训练预算偏离冻结论文协议

冻结协议要求三条 clean Standard 父策略为 u400；当前激活配置却设置 `total_updates: 600`，并把 600 加入 checkpoint 列表。u600 的退化直接解释了为什么“训练末端结果”比 u400 更差。

#### 原因 B：把合同不兼容的历史系统当成当前 Standard 对照

历史结果不是当前 clean Standard 的同合同复现。旧结果包含 selector 和不同 TTC 语义，且观测槽位不同。若继续直接比较，会把系统设计差异误写为训练退化。

#### 原因 C：当前 clean Standard 父策略能力只是边缘可用

u400 三种子 CFMS 均约 0.40，超时均值约 0.44。它能完成部分最终难度任务，但还不足以无条件支撑“从已具备稳定任务能力的 MAPPO 出发并保持能力”这一强叙事。

### 5.2 强证据支持，但尚未被因果消融确认

#### 原因 D：策略动作与冻结安全执行层高度不一致

u400 三种子中：

- raw action norm 为 0.509–0.644；
- executed action norm 只有 0.379–0.391；
- shield delta norm 为 0.498–0.667；
- 初始联合保护介入率为 0.569–0.654；
- material intervention 为 0.699–0.804；
- 安全吸收固定点 episode 比例为 0.25–0.35。

这不是 Actor 完全不输出动作，而是 Actor 输出被执行层显著改变。seed-23 u400 的汇总进一步显示 persistent safe-brake timeout rate 为 0.425，与总体 timeout 0.500 同时出现。这一模式正好支持 CSA 的研究动机，但也说明当前父策略能力存在真实风险。

#### 原因 E：从 u400 继续完整训练可能导致策略锁定或过度保守

u400 到 u600，三个种子的 action std 都继续下降；seed 23 从 0.510 降至 0.434，seed 41 从 0.486 降至 0.443，seed 67 从 0.471 降至 0.425。它与 seed 23/41 的性能退化同时发生，但没有冻结熵系数或学习率的对照实验，因此只能写成相关性假设，不能写成确定因果。

### 5.3 当前证据不支持的解释

- **不支持“数值发散”**：已有日志和指标未显示 NaN、Inf 或异常退出。
- **不支持“只是坏 seed”**：三个种子在 u400 都集中在 0.40–0.425。
- **不支持“布局随机变难”**：历史与当前在同一 40 layouts 上仍存在明显超时差距。
- **不能归因于 CSA-MAPPO**：当前结果是 Standard 父策略训练，CSA 的正式效果尚未产生。

## 7. 主要发现（按严重性排序）

### F01 — Critical — 旧结果与当前结果被放在了不兼容的合同上比较

- 维度：D1、D3、D6。
- 证据：历史 `"obstacle_slots": 6`、`"version": "facs_star_v0"`、`"version": "causal_ttc_progress_projection_v2"`；当前为 `"obstacle_slots": 8`、`"version": "disabled_archived_v1"`、`"version": "causal_ttc_projection_v1"`。
- 影响：不能把 0.68→0.40 解释为同一方法性能退化，也不能用旧结果证明当前 clean parent 合格。
- 修复：所有论文主表和能力陈述只使用同合同结果；旧结果单列为 historical integrated system。

### F02 — Major — u600 偏离 u400 冻结协议且显著退化

- 维度：D5、D6。
- 证据：激活配置为 `total_updates: 600`，正式协议要求 `matching_standard_u400`。
- 影响：`evaluation_summary.json` 当前指向 u600，容易让人错误地将末端模型当成正式父策略。
- 修复：三种子统一固定 `update_0400.pt`；报告不得混用每个 seed 的事后最佳 checkpoint。

### F03 — Major — 父策略能力门槛缺失

- 维度：D2、D3、D4。
- 证据：正式协议定义了 CSA 成功门槛，但未定义 Standard parent 何时有资格进入后续训练。
- 影响：如果父策略本身超时过高，CSA 的“保持任务能力”主张会失去清晰参照，后续失败也难以归因。
- 修复：在查看 119000/120000 面板之前冻结父策略资格规则，并明确规则是本次负结果之后新增的 protocol amendment，而不是事前注册。

### F04 — Major — 高介入与安全吸收固定点使超时成为主要失败模式

- 维度：D1、D4、D6。
- 证据：u400 material intervention 均值 0.742、timeout 均值 0.442；同 layouts 比较中历史 8/40 超时，当前 seed-23 为 20/40。
- 影响：这既是 CSA 的直接动机，也是父策略可能不满足“已稳定具备任务能力”的原因。
- 修复：在不触碰正式测试集的前提下，对现有 u400 做完整暴露面板诊断，并按 Initial Guard、TTC、SAFE_BRAKE、Recovery 分阶段归因。

### F05 — Minor — u400→u600 的熵下降与退化仅为相关性

- 维度：D1、D3。
- 影响：论文中不能写“熵下降导致性能退化”。
- 修复：当前只表述为待检验假设；若未来需要因果结论，必须有固定其他条件的学习率/熵或早停消融。

## 8. 后续决策建议

### P0：立即冻结解释口径

1. 正式父 checkpoint 仅使用三个 `update_0400.pt`。
2. u600 保留为负结果，标记为“额外训练退化证据”，不删除、不覆盖。
3. 不采用 per-seed best 混合选择。
4. 历史 0.68 只称为“旧集成合同下的历史能力证据”。

### P1：先做父策略资格确认，再训练 CSA

建议下一步（需另行授权后执行）是在已经暴露的 117000–117199 development layouts 上，对三个 u400 checkpoint 各做 200-layout 诊断评估。该面板已经用于开发，结果只能用于父策略诊断，不得进入正式主表。

在评估前冻结父策略资格规则。规则至少应包含：

- 三个 seed 均有非零、方向一致的任务完成能力；
- CFMS 和 timeout 的最低/最高可接受界限；
- agent-agent 与 boundary collision 不得出现系统性问题；
- 合同指纹必须完全一致；
- 资格判定使用共同 u400，不允许事后按 seed 选择 update。

具体阈值应由论文“何谓具备任务能力”的研究定义决定，并明确这是在观察当前负结果后做的协议修订，不能伪装成预注册门槛。

### P2：若父策略不合格，先处理 Standard 合同，不要把问题转嫁给 CSA

若完整诊断后仍表现为约 0.4 CFMS / 高超时，则应暂停正式 CSA 路线，先决定两种合法方向之一：

1. **坚持 clean Standard 论文合同**：重新优化 Standard 训练/早停，但必须重新生成三种子共同父策略，并保持后续所有方法相同合同。
2. **弱化论文前提**：把父策略描述为“具有非零但边缘的任务能力”，相应收缩“保持成熟能力”的主张。

不能把旧 selector/TTC 重新加入 CSA 后仍称为当前 clean Standard 的直接延续，除非整篇论文重新冻结并重跑所有基线合同。

### P3：保持正式面板未污染

- 暂不打开 119000–119039 actor validation 面板；
- 不运行 120000–120199 formal test；
- 不在父策略资格未定时训练 CSA 或 MAPPO-Lagrangian；
- 117000–117199 的后续结果明确标为 development/diagnostic。

## 9. 论文报告措辞

当前可以写：

> 在统一 8-slot clean Standard 合同下，三个 u400 父策略均表现出非零任务完成能力，但 40-layout 诊断 CFMS 约为 0.40，且超时与安全执行层介入较高。该结果支持研究“策略—安全层不一致”的必要性，但尚不足以证明父策略已达到稳定成熟能力。

> 历史集成系统在旧 6-slot、selector 和 progress-aware TTC 合同下取得更高完成率；由于合同不一致，该结果不进入当前正式对比，仅作为历史能力背景。

## 10. 最终判定

- **训练工件状态**：三种子 u400 checkpoint 已存在并且合同一致，可保留为候选父策略。
- **当前父策略资格**：有条件、边缘，不足以直接授权正式 CSA 训练。
- **主要问题性质**：协议解释错误和合同不兼容是确定问题；安全执行固定点是强机制证据；熵下降/过训练是待验证假设。
- **正式论文证据状态**：未就绪。
- **下一阶段**：先冻结父策略资格规则，再对现有 u400 在已暴露 development panel 上做完整诊断；通过后才进入 Critic certification 和 CSA 训练。
