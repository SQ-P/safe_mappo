# PPCSA existing-measurement quality audit

The measured six-coordinate protocol completed all 3478 signed/repeated Shadow
calls on 47 states and 328 risk constraints, but returned
`MEASUREMENT_FIDELITY_UNRESOLVED` with no usable sensitivity export. This stage
uses those saved measurements only: no models, parameter perturbations, new
Shadow evaluations, gradients, optimizer or update installation.

## Classification contract

Retain every state, coordinate and observable. Expected analysis units:

| Unit | Count for current fixed report |
|---|---:|
| State-coordinate axes | 47 * 6 = 282 |
| Progress-coordinate observations | 47 * 6 = 282 |
| Risk-track-coordinate observations | 328 * 6 = 1968 |
| All observable-coordinate observations | 2250 |

There are two separate classification dimensions:

- **Amplitude**: exact observed flatness at all signed/repeated scales;
  nonzero response <= the original `1e-7` output floor; or resolved nonzero
  response. No floor, scale or tolerance is changed by this audit.
- **Instability flags (nonexclusive)**: baseline replay/repetition failures,
  endpoint repeat mismatch, Guard/TTC branch signature changes, one-sided
  disagreement, cross-scale disagreement and held-out-scale prediction failure.

`OBSERVED_STABLE_FLAT` requires exact flat values and no detected instability.
It is a finite-probe observation, not proof of zero derivative, a physical risk
plateau, execution absorption or full differentiability. Zero-baseline and
positive-baseline flat risk counts are separated without inferring their causes.
Small **nonzero** responses remain `RESOLUTION_LIMITED_NONZERO` rather than
being relabelled flat. Nonzero consistent responses receive only
`LOCAL_RESPONSE_CONSISTENT`; they are not exported as a favorable subset.
Any detected instability is preserved, including overlapping flags, regardless
of response amplitude. Invalid measurements retain all expected observable IDs
with `INVALID_MEASUREMENT`, never a favorable or flat classification.

Stage/repeat flags apply to the entire axis as contextual evidence, while
numeric consistency failures are localized to individual observables. A stage
switch does not prove a causal effect on any particular track's risk.

Re-run the unchanged pure finite-difference analyzer on saved samples only and
compare its status, flags, errors, estimates, resolution indices and export
decision to each original axis result. Any discrepancy is `INVALID_EVIDENCE`.
The audit explains the old vetoes; it does not revoke or bypass them.

## Provenance and coverage

Bind the full historical chain through admission, endpoint feasibility, common
veto review, original measurement source implementations and frozen measurement
protocol. Verify every referenced source/checkpoint/artifact SHA, the original
six-coordinate map and parameterization SHA, registry identities, all ordered
risk tracks and complete signs/scales/repeats. Hashes are checked again before
writing only the new audit outputs. Structural omissions, source mismatch or
unrecorded invalid evidence stop with an error; no partial-cohort output is
produced. A historically recorded `INVALID_MEASUREMENT` is allowed through
preflight only when the unchanged analyzer reproduces its invalid verdict,
errors and flags from the complete saved signed samples. Such entries remain
invalid in the full quality audit. Preflight does not perform quality aggregation.

The full audit includes per-state, per-coordinate, per-risk-constraint summaries,
per-observable numeric evidence and original JSON pointers, stage-switch fields,
nonexclusive flag counts and overlapping axis-flag patterns. All eight common
veto constraints retain their six-coordinate coverage. Track identities include
layout, step, observer and track; repeated local IDs are not globally merged.
Counts are dependent exploratory units, not independent sample sizes.

The original `parameter_sensitivities=null`, zero-tolerance admission conditions,
measurement status, signed samples and parameter basis remain unchanged. No flat
or unknown entry is removed or zero-imputed. No usable matrix is generated by
this audit, even when some individual responses appear consistent.

## Commands

Preflight only checks source, shape, identity and complete input coverage. It
does not run the full quality aggregation and creates no result directory:

```powershell
Set-Location E:\Code\diagnostic\mappo_safe
python -B scripts\review_ppcsa_sensitivity_quality.py --sensitivity-report results\ppcsa_seed23\parameter_sensitivity_v1\parameter_sensitivity_report.json --output-dir results\ppcsa_seed23\sensitivity_quality_v1 --preflight-only
```

After code review, the user runs the actual offline aggregation:

```powershell
python -B scripts\review_ppcsa_sensitivity_quality.py --sensitivity-report results\ppcsa_seed23\parameter_sensitivity_v1\parameter_sensitivity_report.json --output-dir results\ppcsa_seed23\sensitivity_quality_v1
```

Use a new separate destination. Outputs are `sensitivity_quality_report.json`
and `.md`. Stdout gives status and the detail path. Original raw measurements
are referenced rather than duplicated in the aggregate output.

`QUALITY_AUDIT_COMPLETE` means evidence classification completed, not mechanism
efficacy. `QUALITY_AUDIT_HAS_INVALID_MEASUREMENTS` keeps invalid recordings visible;
`INVALID_EVIDENCE` indicates an original-diagnostic reproduction mismatch.
Actual cause proportions and the next research choice must be read from the
user-run report. This implementation does not authorize threshold tuning,
dimension expansion, a new Shadow run, Actor training, Critic refit, Gate3 or
Audit/formal panel use.
